# Staged D8P1 project-state adapter

Prepared on `dabbl8/d8p1-project-state`, based on the audited byte codec in PR #46. `d8p1_project.h` is included after the real project importer in an eight-track translation unit. It is not included in the shipping firmware and does not adopt engine state or write flash.

The adapter keeps native musical project fields and a distinct bounded arrangement: four banks, sixteen scenes and sixteen scene/repeat rows. The historical `project_t.chain` must be empty in new state. A bank owns eight explicit project/track references; a scene owns an explicit bank reference, application mask, mute mask and signed pan/transpose values. No historical C layout is serialized into D8P1.

Encoding validates every active native field before touching the destination or written count, then emits directly into the caller's output buffer. It does not allocate a second complete payload scratch buffer. Decoding validates the complete byte file, reference availability, source/destination overlap and actual motion decoder before writing staged state. Unknown optional data stays inspect-only in the byte codec and cannot become native state. Structurally valid global and parameter values are retained; runtime engine/global policy checks and actual adoption remain separate responsibilities.

Legacy conversion uses the actual unchanged FUN1–FUN9 importer and its DIGITAL/SAMPLE PERC/PHYS migrations. Caller-owned staging workspace keeps failed imports away from published state and reports. Exact standalone, aligned records are required; retained-slot tails, unaligned historical casts, unknown formats and damaged checksums refuse. Tracks 1–4 retain canonical imported semantics, while tracks 5–8 receive native defaults, empty REST steps and initial FM6 patches. Original bytes remain untouched and must still be preserved by the surrounding file/backup workflow.

Old chain rows mean saved-project slots. Conversion creates one bank and one scene for each referenced slot in ascending slot order, maps all eight source track indices explicitly, and preserves row order and repeats through a slot-to-scene report. Application masks are zero because historical chains use source patterns/timing with current sounds and mix. Missing referenced project bits refuse before publication; slots 2/3 never alias 0/1. The availability mask is supplied by the caller's verified context, not discovered by this adapter. No arrangement playback is implemented here.

Known-file state encoding canonicalizes framing and optional count-zero omission. It is a semantic conversion, not preservation of every legal framing variant; the surrounding workflow must retain the original file. Native runtime metadata such as the old project hash is reconstructed for staged state, never emitted as a historical disk record.

Targeted checks currently pass 18,193 assertions in normal and upstream-configured ASan/UBSan modes. Both independent canonical known files round-trip byte-exactly. All thirteen frozen legacy originals round-trip through D8P1, match the unchanged upstream canonical FUN9 references, and leave originals/references pristine. Tests include all truncations, native field-family failures with unchanged output, source/target/report alias guards and report preservation, unavailable project references, damaged legacy checksums independent comparisons of row/project destinations and repeats against the real unchanged legacy importer, and a full track-8 step-64 chord/drum/chance/ratchet/signed lock alongside a distinct track-4 event. Pure byte-codec strict sanitizer tests remain separately integrated.

The pinned JieLi compiler accepts the adapter within the real eight-track firmware translation unit, producing LLVM IR only. Its `sizeof(d8p1_project_state)` is 9,536 bytes, matching this host. No target link, arena/cache allocation, stack fit, timing, physical test, browser file workflow, save adoption or new-format power-cut result is claimed. The new state/workspace API has caller-owned storage requirements; these are not a firmware allocation decision. The complete integrated suite passes; exact source, fixture and artifact hashes, raw test sections and commands are retained in [the evidence](evidence/2026-10-10-d8p1-project/README.md). Hosted verification remains pending the draft. No map is selected, and no loader, flash boundary, audio golden or vendor firmware is changed.

Caller workspace may contain unrelated prior data. Legacy conversion clears the complete staging object, including padding, before parsing and publishes its canonical representation only on success. A reproduced pre-filled-workspace failure and fix are retained in the evidence; full final-source verification is being repeated.
