# Standalone D8P1 proposal-1 byte codec

This implements the bounded byte-file part of the [storage proposal in PR #26](https://github.com/grant-vine/dabbl8/pull/26), at specification commit `ea624c78bff602ba5edb17e3ec5acf1a59c76241`. It is preparation for #7/#11/#13, not a selected storage map or a completed save path. The module is not included in `felucca.c` and does not change a historical FUN layout, loader, flash boundary, shipping package or audio golden.

`firmware/src/d8p1.h` exposes a borrowed immutable file view, a canonical writer and a project-reference availability check. Header fields and chunk integers are explicit little-endian bytes; no native C project struct is serialized. File CRC treats its four-byte CRC field as zero; each payload also carries standard CRC-32. Six mandatory chunks and optional banks/scenes retain the proposal's exact sizes and count-derived bounds. The maximum known file is 7,705 bytes, independently limited to 7,936 bytes by the parser. Count-zero banks/scenes are defaults when absent. All eight tracks still share the proposed 64 motion records.

A read returns 0 for refusal without changing its destination, 1 for a structurally known file, or 2 for bounded inspection of an unknown optional chunk. The original bytes must stay alive and immutable for the lifetime of the view. Unknown required chunks refuse. Unknown optional imports remain read-only; writing or granting reference eligibility revalidates the original so clearing the flag or removing an unknown view entry cannot silently discard it. A caller may deliberately construct a new known view, but this is not a lossless conversion of an unknown import.

The writer validates all fields, references, capacity and source/destination overlap before touching the destination or written count. It emits increasing base chunk IDs. Globals retain their signed LE16 representation, parameters are bounded to the format's -64–127 range, and preset bytes retain legacy sentinels without reinterpretation. Full engine-specific parameter/global policy validation is a future runtime-adoption responsibility. Packed step probability retains FUN9's internal default/encoded-percent convention, rather than substituting the editor's displayed percentage. Motion IDs and values match the pinned upstream policy. Banks cannot alias missing project slots; passing an availability mask is only a reference check, not permission to play or write flash.

The pure C tests cover every truncation, single-bit corruption, repaired-CRC invalid fields, duplicate/missing chunks, reserved/version/length fields, signed motion boundaries, duplicate addresses across lock kinds, correctly sized missing bank/scene references, output preservation, alias refusal and deterministic malformed inputs. The three committed `.d8p` files are synthetic public fixtures produced independently with Python's `struct` and `binascii`, not vendor firmware or private projects. Re-encoding known files must match these bytes exactly. A separate actual-Felucca test round-trips the maximum motion chunk with `motion_v1_decode`/`motion_v1_encode` and compares every parameter with both lock kinds to `motion_param`.

The regular host suite runs these tests and strict ASan/UBSan for the standalone codec, with none of the upstream DSP sanitizer exclusions. The actual-Felucca compatibility test uses the existing upstream sanitizer configuration because it includes the engine sources. See the retained evidence alongside this document for exact commands, outcomes, omissions and hashes.

No project-state adapter, legacy-to-D8P1 conversion, browser upload/download round trip, target-linked RAM/stack fit, firmware cache adoption, flash A/B publisher or power-cut proof is implemented here. The buffer API needs caller-owned input/output storage; it is not a streaming encoder or a firmware allocation decision. Scene/bank bytes are a proposed representation, not implemented arrangement playback. These remain open gates, as do physical MIDI, IRQ/stack/timing qualification, recovery testing and release evidence. No storage map is selected and no flash writes are authorized by this module.
