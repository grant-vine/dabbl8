# Native three-project menu preparation

The experimental eight-track build now routes manual save, load and rename through the native shared-pool runtime after explicit validated native binding. PROJECT shows three identities, A–C, while the frozen historical four-slot cache and global descriptor remain unchanged for conversion. Active UI/editor descriptors limit slot selection to three. Out-of-range native menu, graph and editor queries cannot alias an available identity.

A 64-byte target pool allocation holds trusted synchronous callbacks, a validated three-name inventory and ownership/readiness flags. Drawing reads only that cache; it never accesses flash or borrows the project/display arena for catalog work. Status identifies migration-required, ready and storage-error states. A failed catalog refresh hides stale names and marks inventory unready while retaining native ownership. Save and rename refuse before callbacks until a separate successful rescan restores current inventory. The actual SAVE action also refuses before deciding whether a slot needs overwrite confirmation, so storage recovery cannot turn a hidden occupied slot into an unconfirmed overwrite. Verified writes refresh inventory even after failure, because an error can occur after a record has committed. Live name/manual identity publish only on controller success.

Binding requires explicit completed-migration authorization, stopped transport and an inactive canvas. Unauthorized or busy attempts perform no storage access. A binding that reaches failed preflight retains native ownership in an offline state rather than falling back to historical RAM slots. Cold initialization revokes all transient callbacks and ownership. The existing-driver adapter exposes the binding entry point, and the [connected editor session](native-migration-session.md) now performs controlled software adoption/binding, including explicit read-only native resume. **No implicit boot/menu/header recognition grants ownership, and shipping writes remain quarantined.** This is software integration, not a qualified device migration or release.

All eight-track legacy project/autosave writes are refused at the storage entry point before reads, erase or program, including before binding and after a cold boot. Settings and preset allocations remain separate; their eight-track application writers are also quarantined. Historical four-track behavior retains its original graph indexing and descriptor expressions. Native arrangement playback and quiet-time shared autosave policy are now implemented in software. Explicit native resume validates a new post-boot capture and consent before adopting persisted state and establishing a read-only session. Automatic boot adoption, qualified full backup/restore, original-preserving physical migration and production write activation remain unfinished. Expanded firmware therefore advertises no complete native backup capability and continues to reject legacy project load/save editor commands.

Current status above reflects firmware main `c8ee5b0f12fa04f32c93168d01839da1a98c9c74`. Source-pinned build sizes, hashes, test counts and linked evidence below describe their original implementation snapshots; they are not fresh current-main measurements.
