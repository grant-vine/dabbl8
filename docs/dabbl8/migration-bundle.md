# Original-preserving migration proposal

This host tool prepares a reviewed initial set for the selected three-project/shared-autosave pool. It does not access a device, erase flash, install firmware or establish recovery qualification. It is a preparation step for issues #11/#13, not completion of the physical migration gate.

## Required originals

Supply a complete current Felucca `.fm1bak` archive and a separate raw 8192-byte snapshot of the historical two-sector autosave allocation. The archive must contain all 13 known objects: current live music, settings, four saved projects, preset/patch banks and three sample objects, including empty objects. The existing companion validator checks IDs/order, bounds, base64, object CRCs and sample headers/zones/data CRCs. Older incomplete archive variants are retained but refused for this migration; capture a complete archive through a separately qualified path.

**A standard backup does not contain persisted autosave.** Its object 0 is live music. It cannot prove the content of the last persisted autosave. No qualified command for capturing that raw pair is supplied here; device export/provenance and recovery remain gates. Do not fabricate a snapshot from live music or assume an absent snapshot is empty.

The tool retains the exact raw archive, both exact autosave sectors and all decoded archive objects before attempting conversion. Original project 4 is validated with its original reference identity and archived only. It is not overwritten, aliased to a native slot, or emitted as a fourth native project. Native candidates use original slots 1–3 with the concrete nonempty reference mask; any candidate or live/autosave project referencing the archived fourth slot is refused. A later explicit mapping workflow could resolve such a project, but this tool makes no such choice silently.

## Autosave selection

The selector follows the historical little-endian FELU header, object type 9, copy ID, bounded payload, header and payload CRCs, and modular generation ordering. It chooses a recoverable CRC-valid copy, including generation wrap or fallback from a bad payload CRC. Identical equal-generation copies choose copy A. Equal-generation divergent data or half-range generations are refused. A CRC-valid foreign header, including the retired FM6-bank identity formerly using this allocation, prevents migration.

Only **both sectors entirely erased to `0xff`** permit explicit initialization of native autosave from the validated live backup. The report identifies that choice. Corrupted/nonempty records are not treated as erased. A recovered record that the pinned project importer cannot understand causes refusal rather than silent substitution of live music.

## Local preparation

Run from a built firmware checkout. Use an isolated Python environment, Node and the native host compiler. Generated binaries and real user originals belong in private ignored directories outside public evidence.

```sh
clang -O2 -w -Ibuild/gen -Ifirmware/src firmware/src/d8p1.c \
  tools/dabbl8_project_convert.c -lm -o /private/tmp/dabbl8-project-convert
clang -std=c11 -O2 -Wall -Wextra -Werror -Ifirmware/src \
  firmware/src/d8p1.c firmware/src/d8pool.c tools/dabbl8_pool_initialize.c \
  -o /private/tmp/dabbl8-pool-initialize
python3 tools/dabbl8_migration_bundle.py /path/to/original.fm1bak \
  /path/to/new-private-proposal --autosave /path/to/raw-autosave-pair.bin \
  --converter /private/tmp/dabbl8-project-convert \
  --initializer /private/tmp/dabbl8-pool-initialize
```

Existing destination directories are refused. The report records hashes of originals, selected autosave, conversion artifacts, host executables and virtual pool bytes, plus conversion/engine changes and native readback. The selected autosave and live music are converted separately; neither original is lost when they differ. All conversions must pass the actual C importer, native structural check and canonical readback before the initial pool is proposed.

`proposed-virtual-pool.bin` is generated by the actual `d8pool_save` writer into simulated NOR and reloaded through `d8pool_load`. Present projects and autosave have distinct committed records, with one shared spare left erased. Geometry is attached from the selected storage plan. **The 40960-byte image is a virtual concatenation, not a contiguous physical flash range.** Its fifth block uses a noncontiguous historical allocation; this file is not suitable for writing directly to a device or submitting to a firmware updater.

Refusal preserves supplied originals and validated decoded archive objects and removes generated project/pool proposals. The source files stay untouched. If an input exceeds the bounded host size, it remains at its source rather than being copied indefinitely. `accepted` means a verified offline proposal only: `device_writes`, `migration_executed`, `firmware_package` and `hardware_qualified` remain false, and `review_required` remains true.

## Evidence and remaining work

[Focused evidence](evidence/2026-10-10-migration-bundle/README.md) covers complete synthetic archives, persisted/live divergence, all originals including a valid ADPCM sample, deterministic initial pool bytes, erased pair initialization, wrap, corruption fallback, ambiguity/foreign records, fourth-slot and missing-reference refusals, damaged projects/samples/archives and exclusive output behavior. The standalone pool initializer uses strict ASan/UBSan; the converter retains documented upstream DSP sanitizer exclusions. The normal and sanitizer cases are included in `tests/run_tests.sh`.

This change adds host tooling/tests only. Firmware sources, loader, physical flash boundaries and golden audio data are unchanged from the parent runtime-persistence commit. It makes no new target memory or hardware claim. Physical original capture and provenance, complete qualified restore, an interruption-safe authorized device migration executor, mapped flash backend, three-slot editor/menu/cache wiring, autosave scheduling/boot hooks, full stack/interrupt bounds and actual audio/MIDI/device qualification remain required before issue #13 can close or firmware can be offered for installation.
