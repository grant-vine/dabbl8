# Checked competing workspace callers

This slice extends the exclusive main-loop migration-plan arena with operational refusal paths. It does not activate migration, grant storage ownership or permit application writes. The eight-track pre-migration write quarantine remains closed.

Historical project name and used queries return `-D8POOL_BUSY` when the canvas or migration lifetime owns the arena. A refused name query leaves its caller buffer unchanged; other valid empty/offline outcomes retain their prior clearing behavior. UI name prompts, graph name snapshots and editor callers distinguish this negative value from empty or used. Graph names publish only after the entire refresh succeeds. Legacy editor project/backup transactions refuse without a success reply when their existing framing has no suitable error field.

Historical project load, restore, boot and autosave use a checked LCD fence before staging. Historical song-chain preparation acquires once before publishing its configuration or sources, validates the available three manual slots directly, and returns its existing busy result `2` on refused ownership while preserving the previous complete chain. They defer before modifying project wires, autosave accounting or boot state when the fence is unavailable. Already-decoded project input at the arena origin reuses its completed fence only when canvas validity is cleared and neither canvas CPU drawing nor migration owns the arena. Compile-time layout assertions bind the decoded project to that arena origin. Fetch work reuses its caller's completed fence rather than creating a second nested acquisition after state has been staged.

All operational UI canvas begins use a checked primitive. Early refusal and acquisition during LCD completion return before canvas geometry/pixels change. One-shot text follows the same rule. UI redraw remembers deferred work even when outer drawing code would clear its force flag, including a refused one-shot whose owner releases before the next UI frame. The unchecked project/canvas primitives remain only invariant checks; operational busy policy does not rely on traps.

The focused fixture uses actual project, editor dispatch, settings/legacy boot, autosave and UI implementations with simulated NOR and LCD completion. It checks held-plan and LCD-late nested acquisition, whole-arena preservation, current project/metadata/catalog/session preservation, raw length and name outputs, prompt state, absence of false editor confirmation, and recovery after release. No physical device or real flash is accessed. Runtime sanitizer coverage inherits the documented engine exclusions; this is not strict qualification of every DSP operation.

Four-track behavior must remain byte-identical to the actual frozen parent target. Fresh four/eight target and full-suite evidence is required after functional source freeze. The historical four-track baseline remains separate, and existing eight-track USB/ROOM/SPRING budget failures cannot be waived by this caller change.
