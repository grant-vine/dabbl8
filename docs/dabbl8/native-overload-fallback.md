# Native overload fallback

Eight held lead/bass notes can protect the entire shared eight-voice budget. Main before this fix can request shedding repeatedly while retiring none. The native-only fallback remembers the oldest protected note during the existing held-voice search, and uses it only after the existing released-tail and extra-held-note choices fail and two consecutive completed halves exceed the existing 85% threshold. Continuing overload can retire further notes; recovery restores protection. Auxiliary IRQs and isolated slow halves do not activate the fallback.

Native retirement is immediate, as for admission; it does not add an overlapping ninth fade voice. Smooth audible transitions remain a release gate. Four-track firmware retains its original protection and fade policy.

Focused actual-ISR tests use a simulated clock/DMA. Four-track tests pass24 assertions and native tests pass66 in normal and inherited ASan/UBSan builds, covering sustained overload, mixed MONO/LEGATO/POLY leads, UNISON, a POLY bass at a nonzero slot, release/extra priority, recovery, auxiliary IRQs and PHYS note-off/retrigger. The regression fails against unchanged native main at the first expected retirement. The initial priority fixture released an unstarted envelope before rendering; it failed and was corrected to release a live envelope after the two overload halves. Its raw failure remains in evidence.

The first implementation at d4002ed reused admission's helper, adding an unnecessary voice search. The final single-pass refinement matches its retirement trace in65,536 generated voice-state cases under normal and inherited sanitizers (seed DABB1801, trace cccef98fda6fcc91). Both focused ISR modes still pass. Independent source review found no correctness defect in the refinement; this is not an exhaustive hardware or numerical proof.

Four fresh pinned target builds of the refinement preserve four-track app/object/ELF byte identity. The native app grows64 bytes (480,220 to480,284), with RAM96,068/98,304 and pool335,240/344,064 unchanged. Static IRQ score is55,767 versus main55,722; UAC remains555. Both native controls and candidate fail the unchanged limits. The local IRQ allocation is440 bytes versus main436 and the first implementation444; it excludes wrapper/callee/nested stack and is not a high-water measurement.

The first implementation scored133,953: its compiled cold fallback jumps backward from after the return epilogue, and the existing branch-span heuristic treats these forward-execution joins as broad loop spans. The refinement removes the extra search and those joins. No limit, heuristic or golden was changed, and no elapsed-time gain is claimed from the score alone. Initial target logs and source pins are retained separately from final single-pass evidence.
