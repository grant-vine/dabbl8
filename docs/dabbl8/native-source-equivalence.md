# Read-only native source equivalence

This dormant internal component compares an already received 40,960-byte native plan with actual historical storage and an explicitly selected PERSISTED or CURRENT autosave source. It performs no writes, binding, live adoption or permission grant. Eight-track application-write quarantine remains closed.

The caller must already own the migration arena with preflight phase 1 and every plan byte received. The checker does not call `d8mp_validate`, change its phase, or accept a caller validation receipt. Its independent actual pool view checks canonical objects, references, padding and erased unused blocks. A later executor still requires its own real phase-1-to-4 canonical validation. All plan bytes remain unchanged; only the existing single project-state/wire staging area is reused. No second project buffer is allocated.

Physical reads are fixed to original roles 0 through 4 and limited to one 256-byte read per step. Both complete sectors receive raw CRC, header/type/copy/body CRC and exact FUN framing checks. Non-erased torn/foreign sectors, equal or half-range sequences refuse. Wraparound uses modular latest-generation ordering. Every committed generation receives the actual frozen FUN1–9 importer, including archival fourth-slot and unselected persisted-autosave bodies, with the original four-slot availability mask. Selected manual 0–2 and PERSISTED autosave conversions are canonical-encoded and byte-compared to actual plan records under the actual three-slot target mask. Fourth-slot references are never remapped. An erased persisted autosave refuses PERSISTED; CURRENT is a separate explicit choice.

CURRENT privately captures the actual stopped runtime in the already-owned stage under the existing IRQ guard, canonical-encodes it, and compares every byte to the plan autosave. The public runtime capture API remains BUSY under migration ownership. Completion stores only small disjoint metadata: generation, plan CRC, source CRC context, current length/CRC, mutation epoch and USB lifetime. No retained stage pointer acts as a receipt. Current capture is repeated at completion and consumption; plan CRC is checked at initial/final validation and consumption. Physical callback boundaries recheck ownership, stopped state, mutation epoch, USB configuration/reset, flash availability and timeout. Initial reservation refuses recursive BEGIN before callbacks.

This CURRENT identity is established from actual RAM during this new checker lifetime. It is **not** a binding to an earlier retained 17-role instrument capture. A future trusted coordinator must bind the privately frozen completed capture's raw CRCs, current length/CRC, epoch, USB lifetime and token before plan transfer. External originals retention, provenance, consent, musical/device equivalence and production ownership remain unproved by this component.

Read/valid callbacks are private trusted main-loop callbacks and must not reenter staging or independently mutate source storage/plan bytes. Epoch and a final raw CRC rescan detect observed writers and earlier source changes; they do not create an atomic external NOR snapshot. Four explicit diagnostic cases demonstrate that an unobserved external mutation behind the final already-scanned range can retain a CRC-consistent result. The initial expanded run incorrectly expected detection in those four cases; its 363,996-check/four-failure log is preserved. These diagnostics are not corruption-detection successes. The future coordinator must retain quarantine, serialize real writer/driver boundaries, and independently reread originals immediately before its first erase (the bounded executor already does that). Arbitrary direct-memory mutate/revert is likewise outside per-step observation; no 40-KiB CRC is performed on every 256-byte read.

The actual simulated-NOR/UI/runtime fixture covers sparse source masks and both choices, all 13 immutable historical fixtures, archival semantics, genuinely different generation bodies and wraparound, ambiguity/torn/foreign/FUN/hash refusals, callback I/O failures, owner loss/reentry, observer-hooked late changes, USB/config/flash/timeout revocation, current and plan mismatches, completion reuse and input aliases. Existing immutable FUN6–9 fixtures with fourth-slot chains conservatively refuse as selected target sources; archival fourth-slot validation remains supported with original context. It accesses no device. Focused strict address/undefined sanitizer checks use no inherited DSP exclusions; full upstream runtime scopes retain their documented exclusions.
