# Bounded native storage preflight scans

Native storage operations previously repeated a complete shared-pool inventory for each selected object while validating the set. Preflight now scans the full pool once, copies each selected body against that scan's CRC and actual codec/reference policy, then scans the full pool again and compares every selected identity before accepting the staged catalog or write preflight. This retains late foreign/future/changed-record refusal while avoiding repeated scans per object. No trusted inventory is cached across operations.

Stopped transport, display/migration ownership and mutation epoch are rechecked. A private byte excludes recursive persistence calls that enter preflight; it is not a transaction-wide lock or protection for arbitrary callback calls to drawing/capture APIs. Existing synchronous backend contracts remain required. Subsequent operation-specific loads, shared-spare commits, physical maps, loader and shipping write quarantine are unchanged.

[Evidence and raw logs](evidence/2026-10-11-shared-pool-preflight/README.md) compare an unchanged production-source control with the candidate. Full catalog backend bytes fall about 51.8%; full autosave snapshot bytes fall about 42.9%; sparse one-object catalog traffic is unchanged. Two host modes pass the new late-boundary/reentry tests and seven existing runtime/storage suites. Host callback traffic is not a claim of device speed, audio deadlines or qualified persistence. Vendor-linked code/RAM/frame evidence and physical recovery qualification remain required.
