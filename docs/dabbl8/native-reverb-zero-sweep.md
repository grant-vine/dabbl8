# Native reverb zero-sweep certificates

Eight-track ROOM and SPRING retain the same coefficient arithmetic, buffer stores, output order and model-clear behavior. Their render loops OR the new stored values into local dirty summaries instead of counting both old and new nonzero entries. At function exit a dirty summary resets a conservative overwrite wait; an all-zero block subtracts its actual sample count, saturating at zero. ROOM waits 1356 comb and 556 allpass samples; SPRING waits 4096 line and four allpass samples. Each active entry is rewritten at least once during that many consecutive zero-write samples. Entire unused union/line regions remain zero from the existing full `rev_clear`. An internal model change without that required clear latches separate tracked-store guards until clear; recognized silence never grants persistence ownership.

These waits are proof metadata, not counts of nonzero entries. Original delay/chorus counting stays intact. Original external tracked comb/allpass disturbance guards remain separate and conservative; ordinary rendering cannot clear them. `rev_clear` resets both guards and certificates only after its existing full buffer clear. No tail is cleared to force a save. The maximum additional certificate wait is about 93 ms for SPRING after the last nonzero block; fixed-point low-pass residuals, voices, DAC/USB queues and other existing conditions may defer autosave longer or indefinitely.

Local summaries are incomplete inside rendering. Main-loop readers require the existing fresh IRQ-off driver check; an interrupt nested in audio rendering cannot use this predicate as write authority. Publication tests exercise actual TIMER5 service and explicitly record unavailable in-flight information. Full independent scans of every line and the entire union, including unused entries and the odd final int16, verify that completed silence certificates imply actual zeros. Tests cover variable block lengths, zero-length calls, wrap, model changes, tracked inactive-region disturbances, conservative expiry, actual rendering, late mutation refusal and postcommit behavior. Synthetic clears in test expiry fixtures are explicit host baselines, never a production eligibility strategy.

[Preserved Mac and target evidence](evidence/2026-10-11-native-reverb-zero-sweep/README.md) records passing paired/full host tests, exact-parent audio and ROOM/SPRING target limits. UAC still fails its original target limit. Physical timing and complete nested stack remain pending. This helper is not a production migration grant or hardware/recovery qualification. Four-track code is unchanged under compile guards; no engine, effect or voice is removed.

External tracked comb/allpass stores latch their separate dirty guard on every update until the existing full rev_clear; they never decrement an occupancy counter shared with uncounted production rendering. Actual mixed render to external-zero to external-nonzero fixtures reproduce the prior underflow/wrap and verify both guard families stay refused through repeated updates. Delay and chorus retain their exact counted semantics. The bounded production render cannot clear these external latches.
