# Eight-track performance solo audio fix

GLO solo previously set ownership correctly in the eight-track UI, but the audio complement still masked only four tracks. Non-solo tracks 5–8 therefore remained audible. The existing four-entry mute-gain initializer also left upper tracks at zero on cold startup, causing an unrelated first performance activation to ramp them into the mix. The fix derives the solo complement from NTRK and explicitly initializes the four additional gains only in eight-track builds. Direct mutes retain precedence over solo. Four-track values and behavior remain unchanged.

The new regression captures the actual static initializer before any reset, asserts all eight full gains and restores that captured state between cases. It compares cold first-block dry/send input with an unrelated track muted; it never manufactures full gains to bypass the bug. It then tests all 256 logical solo masks, 64 actual banked GLO/white-key gesture and candidate-track pairs, direct mutes and their union with solo, and settled release. Its 2240 cases inspect real events/perf_begin/mix_part/perf_pre stages on both dry stereo channels and chorus/delay/reverb sends before wet/master processing. These prove new audio input isolation, not silence of existing effects tails or sample-by-sample ramp shape. Logical mask coverage does not claim all 256 masks are reachable simultaneously with physical keys.

The corrected test fails 2708 of 11328 checks against the exact archived parent `58944ef427494173388a71f1f5cb4d7fee21d1cd`, and passes all 11328 on changed code in optimized and inherited ASan/UBSan modes. Independent review found no concrete defect. Initial harness failures incorrectly observed wet/master output as dry and retained UI key-edge state between cases; they are retained with their corrections. An independent earlier full mix_block probe with dry-only sends reproduced 37 solo failures in 104 cases.

Required normal upstream performance/effects and instruction-cost assertions pass.
